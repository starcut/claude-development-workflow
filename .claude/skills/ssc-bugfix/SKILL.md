# ssc-bugfix

## 目的

既存の不具合を調査し、原因を特定した上で修正する。

## 進め方

1. 不具合の内容と既存仕様を確認する。
2. 不具合の原因特定に必要な範囲を調査する。
3. 調査結果から、原因と修正対象となるファイルを整理し、ユーザーに確認する。
4. 修正方法を判断できるか確認する。
5. 修正方針や仕様上の確認が必要な場合は、修正前に方針を整理し、ユーザーに確認する。
6. ユーザーの確認後、修正する。

## 判断ルール

- 仕様や修正方法について判断できない場合は、推測で決定しない。
- 仕様上の確認が必要な場合は、修正前にユーザーへ確認する。
- 原因と修正対象が明確になるまでは修正しない。

## 制約

- 不具合の原因特定に必要な範囲を超えて調査しない。
- 依頼されていない変更を行わない。
- 不要なリファクタリングを行わない。
- 既存の設計・実装を尊重し、独自の設計変更を行わない。

## 完了条件

- 不具合の原因が特定されている。
- 修正対象が明確になっている。
- 必要な仕様・修正方針についてユーザー確認が完了している。
- 修正が実装されている。
- 変更内容に対して必要な検証が実施されている。
