# ssc-feature

## 目的

新規機能を、既存の仕様・設計・実装を尊重しながら実装する。

## 進め方

1. 依頼内容と既存仕様を確認する。
2. 実装する機能と変更対象となるファイルを整理し、ユーザーに確認する。
3. 実装に必要な範囲を調査する。
4. 設計上の判断や仕様上の確認が必要な場合は、実装前に方針を整理し、ユーザーに確認する。
5. ユーザーの確認後、実装する。

## 判断ルール

- 仕様や設計について判断できない場合は、推測で決定しない。
- 設計上の判断が必要な場合は、実装前にユーザーへ確認する。
- 仕様上の確認が必要な場合は、実装前にユーザーへ確認する。
- 実装範囲が明確になるまでは実装を開始しない。

## 制約

- 依頼された機能に必要な範囲を超えて調査しない。
- 依頼されていない変更を行わない。
- 不要なリファクタリングを行わない。
- 既存の設計・実装を尊重し、独自の設計変更を行わない。

## 完了条件

- 依頼された機能が実装されている。
- 実装範囲が依頼内容から逸脱していない。
- 必要な仕様・設計上の確認が完了している。
- 依頼されていない変更や不要なリファクタリングが含まれていない。
