# ssc-pr

## 目的

実装内容と差分を正確に把握し、変更内容を適切に整理した上でPull Requestを作成する。

## 進め方

1. マージ先のブランチをユーザーに確認する。
2. 現在のブランチとマージ先のブランチの差分を確認する。
3. 差分から実装内容と変更箇所を把握する。
4. 実装内容からPull Requestの概要と変更箇所を整理する。
5. 必要なチェック項目を整理する。
6. ユーザーに確認が必要な事項がある場合は、Pull Request作成前に確認する。
7. 確認後、GitHub上でPull Requestを作成する。

## 判断ルール

- マージ先のブランチを推測しない。
- 差分に含まれない変更内容を推測してPull Requestに記載しない。
- Pull Requestの内容について判断できない場合は、推測で決定せずユーザーに確認する。
- 差分から確認できる事実と、推測・判断が必要な内容を区別する。

## 制約

- 依頼されていない変更を行わない。
- Pull Request作成のために不要なコード変更を行わない。
- 差分に含まれない変更内容をPull Requestに含めない。
- マージ先ブランチを独自に決定しない。
- 実装内容を推測して補完しない。

## 完了条件

- マージ先ブランチが確認されている。
- 現在のブランチとマージ先ブランチの差分を確認している。
- Pull Requestの概要と変更内容が差分に基づいて整理されている。
- 必要なチェック項目が整理されている。
- Pull RequestがGitHub上に作成されている。
