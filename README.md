# Development Workflow

# Skills

このディレクトリには、Claude Codeで開発作業を行う際の作業手順・判断ルール・制約を定義するSkillを配置する。

## 目的

各開発作業において、

* 作業範囲を明確にする
* 既存の設計・実装を尊重する
* 必要な確認を実装前に行う
* 推測による仕様・設計の決定を避ける
* 依頼されていない変更を行わない

ことを目的とする。

## Skill一覧

| Skill          | 目的                       |
| -------------- | ------------------------ |
| `ssc-bugfix`   | 既存の不具合を調査・修正する           |
| `ssc-feature`  | 新規機能を実装する                |
| `ssc-pr`       | 差分を確認し、Pull Requestを作成する |
| `ssc-refactor` | 既存コードをリファクタリングする         |
| `ssc-release`  | リリースに必要な作業を行う            |
| `ssc-review`   | 実装内容やコードをレビューする          |
| `ssc-test`     | テストの作成・実行・確認を行う          |

## 基本方針

### 1. 推測で決定しない

仕様・設計・実装方法について判断できない場合は、推測で決定せずユーザーに確認する。

### 2. 作業範囲を広げない

依頼された作業に必要な範囲を超えて調査・変更を行わない。

### 3. 既存設計を尊重する

既存の設計・実装を確認した上で作業し、必要性がない限り独自の設計変更を行わない。

### 4. 不要な変更を行わない

依頼されていない機能追加、リファクタリング、ファイル変更などを行わない。

### 5. 実装前に必要な確認を行う

仕様や設計について確認が必要な場合は、実装を開始する前に確認する。

## Skillの使い分け

Skillごとに対象となる作業を明確にし、複数の作業を混同しない。

例えば、新規機能の実装では `ssc-feature`、既存不具合の修正では `ssc-bugfix` を使用する。

作業の途中で別のSkillの責務に該当する作業が必要になった場合は、必要性を確認した上で適切なSkillを使用する。

## Commandsとの関係

`.claude/commands/` にあるCommandは既存の明示的な作業入口として保持する。

```text
.claude/
├── commands/
└── skills/
```

CommandとSkillは同一のものとして扱わず、それぞれの役割を分けて管理する。

Skillの具体的な作業手順・判断ルール・制約については、各ディレクトリの `SKILL.md` を参照する。

## 基本方針

* このリポジトリは、複数のソフトウェア開発プロジェクトで共通利用する開発ワークフローを定義する。
* プロジェクト固有の技術・構成・ルールは、利用先プロジェクトの `CLAUDE.md` を優先する。
* 使用する言語、フレームワーク、ライブラリ、ビルド環境、テスト環境などを勝手に決めない。
* 依頼された作業に必要な範囲のみ調査する。
* 不要なプロジェクト全体の調査を行わない。
* 依頼されていない変更を行わない。
* 不要なリファクタリングや改善を行わない。
* 変更範囲は必要最小限にする。

## 調査

* 作業開始前に、依頼内容を理解するために必要な範囲を調査する。
* 既存の実装、設定、テスト、Gitの変更状況などを確認する必要がある場合は、対象を限定して確認する。
* 調査結果と事実を区別する。
* 推測だけで実装方針を決定しない。
* 必要な情報が不足している場合は、自己判断で補完せずユーザーに確認する。

## 設計・実装

* 実装が必要な場合、実装前に必要な設計・実装方針を整理する。
* 設計や実装方針についてユーザーの判断が必要な場合は、実装を開始せず、先にユーザーへ提示して確認を取る。
* 承認されていない設計変更や仕様変更を行わない。
* 作業中に当初の設計・方針では判断できない事項が発生した場合は、追加調査や自己判断で進めず、ユーザーに確認する。
* 既存コードの設計思想や規約を確認せずに独自の方式へ変更しない。

## 検証

* 変更後は、変更内容に応じて必要なテスト、ビルド、静的解析、その他の検証を行う。
* 実行できなかった検証がある場合は、その事実を明示する。
* 検証結果を推測で補完しない。
* エラーが発生した場合は、原因を確認せずに無関係な変更を行わない。

## Git

* ユーザーの依頼なしにコミット、プッシュ、ブランチ操作を行わない。
* 既存の変更を勝手に破棄しない。
* 自分が変更していない差分を勝手に修正しない。
* Pull Request作成時は、実際の変更内容と検証結果に基づいて内容を作成する。

## コマンドの利用

このワークフローでは以下のコマンドを使用する。

* `/ssc-feature` — 新規機能の実装
* `/ssc-bugfix` — バグ修正
* `/ssc-test` — テスト作成・実行・確認
* `/ssc-review` — コードレビュー
* `/ssc-pr` — Pull Request作成
* `/ssc-refactor` — リファクタリング
* `/ssc-release` — リリース作業

各コマンドは、この `CLAUDE.md` のルールに従う。

### 導入方法

プロジェクトのルートディレクトリで以下のコマンドを実行する
```bash
curl -fsSL https://raw.githubusercontent.com/starcut/claude-development-workflow/main/install.sh | bash
```

## 共通ルール

* コマンドの目的を超えた作業を行わない。
* 1つの作業中に別の改善事項を発見しても、依頼されていなければ作業対象に含めない。
* 「より良い方法」が考えられる場合でも、現在の仕様・方針を勝手に変更しない。
* 作業完了時は、実施した内容、変更したファイル、実行した検証、未完了事項を明確に報告する。
